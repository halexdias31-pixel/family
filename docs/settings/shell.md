| SH-001 | Grid | (global) |  | rule | The app is a two-axis grid. X moves between screens, Y moves between the widgets on one screen. Both are swipes. | There is no tab bar and no back button, so the two gestures are the whole of the navigation. | shell.js | TRUE |
| SH-002 | Grid | (global) |  | rule | Screens do not move. They are containers; the pages inside them are what is transformed. | Moving a screen and the page inside it means two transforms fighting for the same pixels, and a scroll position the browser computes from a moving frame. | shell.js | TRUE |
| SH-003 | Grid | (global) |  | rule | The Y axis is absent on a screen that is not paged, and a vertical drag there falls through to ordinary scrolling. | It is what makes a scrolling screen possible without a special case: one page means nothing to page to. | shell.js | TRUE |
| SH-004 | Grid | (global) |  | rule | Only the current cell and its immediate neighbours are painted. | A grid that paints everything rebuilds four thousand cards to move one screen sideways. | shell.js paintNeighbours | TRUE |
| SH-005 | Grid | (global) |  | limit | Travel clamps at both ends. There is no wrap-around. | Swiping past the last screen onto the first reads as the app having jumped rather than moved. | shell.js | TRUE |
| SH-010 | Tabs | (global) |  | rule | TABS is a table. Adding a screen is adding a row, and the axis, the routing and the neighbours all follow from it. | It survived being reduced to a single entry and grown back to four without a special case either time. | shell.js TABS | TRUE |
| SH-011 | Tabs | (global) |  | rule | Every tab needs a matching <section id='s-{id}'> in index.html. | The axis reads its cells by that id. A tab without a section places nothing and swipes to a blank screen — which is what shipped when TABS was pushed and index.html was not. | index.html, observed live | TRUE |
| SH-012 | Tabs | (global) |  | rule | An unknown route falls back to a NAMED screen, not to TABS[0]. | TABS[0] was Find only because Find was written first. The moment a camera took the left-hand end, every unknown route landed on an empty composer. | shell.js TAB_HOME | TRUE |
| SH-013 | Tabs | (global) |  | storage | The current screen is remembered by id in localStorage, and restored if it still exists. | Remembering by index moves somebody's saved position to a different screen the first time the table is reordered. | shell.js AT | TRUE |
| SH-020 | Loading | (global) |  | rule | The whole database arrives in one fetch. Nothing is loaded per screen. | One round trip on a bad connection, then nothing. It is the right trade for a phone in a house with poor signal. | shell.js load | TRUE |
| SH-021 | Loading | (global) |  | rule | LOADED is the difference between 'nothing yet' and 'nothing at all'. A skeleton shows until it is true. | Telling somebody there are no posts while the request is in flight is a lie the app corrects a second later. | shell.js LOADED | TRUE |
| SH-022 | Loading | (global) |  | rule | A failed load says so and offers a retry. It does not show an empty app. | An empty app and a broken app look identical, and only one of them is worth waiting for. | shell.js banner, retry | TRUE |
| SH-030 | Writing | (global) |  | rule | Writes are POSTs with no headers set, so the body goes as text/plain. | Setting Content-Type: application/json makes the browser send a preflight OPTIONS request, and Apps Script does not answer one. The request fails with a CORS message that says nothing about the cause. | me.js send_, api | TRUE |
| SH-031 | Writing | (global) |  | rule | A reply is read as text and parsed second. An HTML reply is surfaced as its own message. | Apps Script answers an uncaught exception with an HTML page saying exactly what went wrong. Calling .json() on it throws 'Unexpected token <' and bins that page unread. | me.js send_ | TRUE |
| SH-032 | Writing | (global) |  | rule | A reply carrying an error field is a failure, even though the request succeeded. | Anything that only checks whether the request went through treats a refused sign-in as a signed-in state. | me.js | TRUE |
| SH-033 | Writing | (global) |  | rule | A button that starts a write is disabled and relabelled until it finishes, and restored either way. | The request is several seconds against Apps Script. A button that still reads 'Sign in' and can still be pressed reads as frozen, and a second press is a second write. | me.js send_ button, busy | TRUE |
| SH-034 | Writing | (global) |  | rule | After a write that changes what is on screen, redraw immediately and refresh the payload behind it. | Waiting for the refetch means you are signed in, the toast says so, and the form in front of you still asks for your name until something else happens to repaint. | me.js do-signin | TRUE |
| SH-040 | Caching | (global) |  | rule | Every file is requested with a version taken from document.lastModified, which moves on deploy and at no other time. | A clock-based version defeats the cache permanently and costs every visitor the whole app on every load. | index.html LOAD | TRUE |
| SH-041 | Caching | (global) |  | rule | ?dev on the address swaps that for the clock, and the footer says so. | index.html cannot date its own URL, so GitHub Pages holds it under its own max-age — and a query string is an address no browser has a copy of. A stale file and a broken feature look identical from the outside. | index.html DEV | TRUE |
| SH-050 | Files | (global) |  | rule | All JavaScript files share one global scope and are concatenated in the order listed in index.html. | There is no bundler and no imports. The order is the only thing the split can break. | index.html FILES | TRUE |
| SH-051 | Files | (global) |  | rule | check.js holds the same order and asserts it matches index.html. It reports every name used but never declared. | It is what replaces the compiler. Two seconds, and it is the whole safety net. | js/check.js ORDER | TRUE |
