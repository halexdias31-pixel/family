# finder

| rule_id | area | step | step_label | kind | rule | because | source | active |
|---|---|---|---|---|---|---|---|---|
| FN-001 | Shape | (global) |  | rule | The finder is a funnel: one question at a time, each narrowing what is left. It is not a search box with filters beside it. | Four thousand items cannot be scrolled and cannot be guessed at. A question you can answer beats a filter you have to know about. | find.js | TRUE |
| FN-002 | Shape | (global) |  | rule | Answering a question adds a chip. Chips can be removed one at a time or all at once. | The chips are the only record of where you are, since there is no breadcrumb and no back button in a funnel. | find.js filter-drop, filter-clear | TRUE |
| FN-003 | Shape | (global) |  | rule | Every item in the list is one of the app's kinds. A kind decides which department it belongs to and which card draws it. | One list holds tutors, venues, worksheets, posts, games and documents. Without kinds they would need separate screens, which is the design this replaced. | find.js KINDS | TRUE |
| FN-010 | Funnel | (order) |  | rule | Questions are asked in the order written in FACETS, overridden by sort_order in the facets tab. | The written order encodes which questions a person can ANSWER at what point — subject before board, board before paper, paper before question number. | find.js facetList, facets tab | TRUE |
| FN-011 | Funnel | (order) |  | rule | The order is NOT computed from how much each question narrows the set. | Built and measured. Scoring by expected remaining size picked 'Question' (50 answers) before 'Subject' three times under three different constraints. Information gain always prefers many small piles to few large ones. | measured, reverted | TRUE |
| FN-012 | Funnel | (order) |  | rule | A question is skipped when fewer than two of its answers exist among the items left. | A question with one answer is not a question. | find.js nextFacet | TRUE |
| FN-013 | Funnel | (order) |  | limit | A question is skipped when fewer than half the items left can answer it. The facets tab can lower that bar per facet with min_coverage. | Asking about exam board on a screen of primary worksheets offers an answer that hides almost everything. | find.js FACET_COVERAGE = 0.5 | TRUE |
| FN-014 | Funnel | (order) |  | rule | When no question is left, the list says 'Nothing left to narrow' and shows what remains. | A funnel that simply stops looks broken. Saying so is the difference between finished and failed. | find.js | TRUE |
| FN-020 | Answers | (any) |  | display | Each answer shows how many items are behind it. | It is the only way to tell a useful question from a pointless one before answering it. | find.js facetValues | TRUE |
| FN-021 | Answers | (any) |  | rule | A cell holding a comma-separated list counts as several answers, not one. Key stage does this. | A primary worksheet serves KS1 and KS2. Forcing one answer means choosing which half of the audience to hide it from. | find.js keystage facet, asList_ | TRUE |
| FN-022 | Answers | (any) |  | display | Answers are rows that look pressable: a surface, a border, a pressed state. | They were text on a line with a number at the end — the same thing a receipt row looks like. One is a fact, the other is the only control on the screen. | style.css .row.tap.counted | TRUE |
| FN-023 | Answers | (any) |  | rule | An option that does not fit is MARKED with the reason and left in the list, never removed. | A list that quietly drops things seems to have decided for you, and the thing it drops is often the one you meant. | find.js, same rule as booking BK-102 | TRUE |
| FN-030 | Items | (global) |  | rule | Papers and worksheets are derived by grouping question rows on paper_id. They are not stored separately. | Seventeen of the thirty-six fields in the questions sheet never vary within a paper. Storing them twice means keeping them in step by hand. | find.js allTopics | TRUE |
| FN-031 | Items | (global) |  | rule | A worksheet is ONE card. Its questions do not appear as separate cards. | 2,463 worksheet rows across 161 worksheets. Grade 3 showed 186 cards for 11 worksheets, and the screen builds one DOM section per result, which is what made it stall. | find.js questionItems, collapse | TRUE |
| FN-032 | Items | (global) |  | rule | A past paper's questions DO appear as separate cards, alongside the paper. | Question 5 of a past paper is a thing somebody revises and asks for by number. Q17 of a times-tables sheet is not — nobody wants the seventeenth question, they want the sheet. | find.js questionItems, qNumber | TRUE |
| FN-033 | Items | (global) |  | rule | A question row whose kind is 'stem' is never an item. It is the shared preamble for the parts under it. | It has no marks and no answer; it is context, and on its own it reads as a question with the question missing. | find.js | TRUE |
| FN-040 | Search | (box) |  | rule | The search box matches against name, sub, subject, slot, grade AND the text of the question itself. | A question's name is 'Q5b'. Without the question text, none of 3,240 rows was findable by what it is about: momentum, refraction, half-life and hypothesis all returned nothing. | find.js hay, searchText_ | TRUE |
| FN-041 | Search | (box) |  | rule | A collapsed worksheet is searchable by the text of every question inside it. | A bearings sheet whose title says nothing about compasses should still be found by 'compass'. | find.js paperText_ | TRUE |
| FN-042 | Search | (box) |  | rule | Search text is built once when items are built, never inside the filter. | The obvious version strips HTML inside the filter, which runs for every item on every letter typed — three thousand regexes a keystroke. | find.js searchText_, memoised on the payload | TRUE |
| FN-050 | Sort | (list) |  | order | Questions sort by their paper first, then by question number as a NUMBER, then by part. | By name alone a question sorts as 'Q5b', so every paper's Q1 clumped together and Q1, Q10, Q11 came before Q2 — in the one list where the sequence is the whole point. | find.js stuffItems sort | TRUE |
| FN-051 | Sort | (list) |  | order | Everything that is not a question falls through to a plain name comparison. | Its sub is empty and its question number is zero, so the tiebreaks pass over it untouched. | find.js | TRUE |
| FN-060 | Cards | (any) |  | rule | Each kind names the function that draws its card. A real paper gets a paper card laid out like an exam cover. | A past paper has a board, a tier and a session, and they are printed on the front of the real thing. Anything else is an ordinary card. | find.js KINDS, paperish_ | TRUE |
| FN-061 | Cards | (any) |  | display | The second line reads: company, then subject, then year. | It read 'Maths · 2025' on four hundred cards. On a screen already filtered to maths, subject is the one word every card shares — which makes it the one word none of them needed. | find.js thingCard_ | TRUE |
| FN-062 | Cards | (any) |  | display | Company is suppressed on a paper card. | The paper card already prints the board across the top of the cover. Printing AQA twice on one card reads as a mistake rather than emphasis. | find.js thingCard_, paperish_ | TRUE |
| FN-063 | Cards | (any) |  | rule | Every mark on a card is a plate: a surface, a border, a pressed state. Only the colour varies. | The ordinary marks were bare glyphs and the admin ones were on tinted plates. Both are the same act — press a mark and something happens to this card. | style.css .tile | TRUE |
| FN-064 | Cards | (any) |  | rule | Admin marks are yellow and sit at the far end of the row, separated by an auto margin. | A bin beneath a trolley is a thumb's width away; a bin at the opposite end of the row is the width of the card away, and a sideways thumb movement is more deliberate than a downward one. | style.css .tile.is-admin, --admin #f2d24b | TRUE |
| FN-065 | Cards | (any) |  | rule | Admin yellow is NOT the gold used for buying. | The trolley on the same row is drawn in gold. One colour for buy and bin is the exact confusion the separated rows existed to prevent. | style.css | TRUE |
| FN-070 | Numbers | (facet) |  | rule | The question-number facet is blank on worksheets and only offered on past papers. | Twenty-five primary topics with ten questions each produced answers reading 1 (25), 2 (25), 3 (25) — a question about position in a document nobody is reading as a document. | find.js qNumber | TRUE |
| FN-071 | Numbers | (facet) |  | rule | Which paper is asked BEFORE which question. | Without it, KS4 Higher pooled three papers and offered numbers 1 to 23 — so 'Question 5' meant six different problems at once. | find.js paperName facet | TRUE |
| FN-072 | Numbers | (facet) |  | rule | The which-paper facet is blank on anything that is not a past paper. | Offering 'which paper' across 161 worksheets is the question-number fault again in a different column. | find.js paperName | TRUE |
| FN-080 | Bands | (facet) |  | rule | Grade, School year and Stage are three separate questions, chosen by band_type. | A GCSE grade 5 and a Year 5 child are different facts. One facet would put '5' next to 'A-Level' in the same list. | find.js bandValue, yearGroup, stage | TRUE |
| FN-081 | Bands | (facet) |  | display | The year-group facet is labelled 'School year', not 'Year'. | There are two: the year group a child is in, and the year a paper was sat. They never collided while no maths resource carried a year group; the primary worksheets now do. | find.js yearGroup | TRUE |
| FN-082 | Bands | (facet) |  | rule | Worksheets carry no tier. Grade does that work. | Tier was derived from grade, and grades 4 and 5 sit on both Edexcel tiers — so it was wrong for a third of them. A worksheet does not have a tier at all. | questions sheet | TRUE |
| FN-090 | Departments | for | What for | rule | The first question names the app's department: Booking, Learning, People, Shop, Tools, Games, Links, Friends, Paperwork. | It separates errands. Somebody looking for the cancellation policy is not revising, and filing a policy under Learning would be answering that question wrongly in order to reach it. | find.js kindOf_, forLabel | TRUE |
| FN-091 | Departments | kind | What kind | rule | The second question names the kind within that department. These two are never reordered. | They are the only two questions whose answers a person always has. Everything after them is a property of what they are looking at. | find.js | TRUE |
| FN-100 | Company | (facet) |  | rule | Company comes from the questions sheet and identifies the publisher: 1stclassmaths, Corbettmaths, AQA, Edexcel, STA. | It was hardcoded empty, so the Company facet had nothing to offer and every worksheet looked like it came from nowhere. | find.js allTopics, questions.company | TRUE |
| FN-101 | Company | (facet) |  | rule | On a screen already filtered to one key stage and one type, the publisher is usually the only thing telling two cards apart. | Grade 5 KS4 worksheets are 26 sheets that share every other field. | observed | TRUE |
| FN-110 | Topics | (facet) |  | rule | The topics column exists on questions and no facet reads it yet. | Deliberate. On worksheets a topic tag mostly repeats the worksheet's own name — 55% of rows — so it adds little. On past papers it is transformative: 62 distinct topics across 74 questions, and nothing else can surface the circle-theorems question. | questions.topics, topicstuff tab | TRUE |
| FN-111 | Topics | (facet) |  | rule | If added, it must be two questions: Area first, then Topic once narrowed. | 75 topics on a phone is a scroll, not a choice. Six areas is a list. | topicstuff tab, parent column | TRUE |
| FN-120 | Speed | (global) |  | rule | The results screen builds one DOM section per item before anything is filled. | This is why collapsing worksheets mattered: 3,441 sections became 978, a 72% cut, and it is the difference between a screen that stalls on the tap and one that does not. | find.js screen('stuff') | TRUE |
| FN-121 | Speed | (global) |  | rule | The item list and the facet list are memoised against the payload object itself. | A new payload is a new array, so one identity comparison decides whether the cache stands. Without it they rebuild on every repaint. | find.js | TRUE |
