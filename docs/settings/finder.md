| FN-001 | Shape | (global) |  | rule | The finder is a funnel: one question at a time, each narrowing what is left. It is not a search box with filters beside it. | Four thousand items cannot be scrolled and cannot be guessed at. A question you can answer beats a filter you have to know about. | find.js | TRUE |
| FN-002 | Shape | (global) |  | rule | Answering a question adds a chip. Chips can be removed one at a time or all at once. | The chips are the only record of where you are, since there is no breadcrumb and no back button in a funnel. | find.js filter-drop, filter-clear | TRUE |
| FN-003 | Shape | (global) |  | rule | Every item in the list is one of the app's kinds. A kind decides which department it belongs to and which card draws it. | One list holds tutors, venues, worksheets, posts, games and documents. Without kinds they would need separate screens, which is the design this replaced. | find.js KINDS | TRUE |
| FN-010 | Funnel | (order) |  | rule | Questions are asked in the facets tab's sort_order, all of them — no question is held in front of the others. FACETS' own order is only the fallback for a facet the tab does not place. | The order encodes which questions a person can ANSWER at what point, and the sheet is where that is decided (396: What for and What kind were held first in code). | find.js facetList | TRUE |
| FN-011 | Funnel | (order) |  | rule | The order is NOT computed from how much each question narrows the set. | Built and measured. Scoring by expected remaining size picked 'Question' (50 answers) before 'Subject' three times under three different constraints. Information gain always prefers many small piles to few large ones. | measured, reverted | TRUE |
| FN-012 | Funnel | (order) |  | rule | ONE RULE ASKS EVERY FACET (396): at least two answers among the items left, at least half of them able to answer, a split worth making (the commonest answer leaves out 2% or more), and no more than 40 answers. No facet has a rule of its own: no doors, no folders asked with one answer, no grids past the cap, no fences, no 'never asked' facets, no per-facet coverage. | Every special case was a place for the funnel to behave differently from what a person had learnt from the questions before it. The owner: 'all the tags to work like the standard ones'. | find.js facetWhy_, nextFacet; check-funnel rule 1 | TRUE |
| FN-013 | Funnel | (order) |  | limit | When nothing passes, the last resort asks the facet held back only for having more than 40 answers that has the fewest. | A dead end is worse than a long question; the fewest answers is the closest thing to a question. | find.js overFacet_ | TRUE |
| FN-014 | Funnel | (order) |  | rule | When no question is left, the list says 'Nothing left to narrow' and shows what remains. A chosen paper is not an end: Question, Part and the rest are asked inside it by the same rule. | A funnel that simply stops looks broken; a paper that ended the funnel was a rule of its own (396). | find.js stuffQuestion | TRUE |
| FN-015 | Funnel | (answers) |  | order | ONE ORDER FOR EVERY FACET'S ANSWERS, by what the answers are: years and dates newest first, numbers by size, month names by the calendar, roman numerals by value, kinds (and their groups) by the kinds tab's sort_order, everything else A–Z with numbers read as numbers. | A table of orders per facet was one more thing to keep in step; the answers say what they are. | find.js answerCmp_ | TRUE |
| FN-016 | Funnel | (answers) |  | display | ONE WAY TO SAY AN ANSWER: its first letter capitalised, unless it is a single lower-case letter or a roman numeral (a part `a`, a sub-part `ii`). The words are the value (Q7, 4 marks, Page 2, Non-calculator, 1 June); only an id (a paper) has a name looked up. | One spelling on the button, the chip and the card. | find.js facetSay_ | TRUE |
| FN-017 | Funnel | (answers) |  | display | Every answer is drawn as the shortest form of its name no other answer shares; two that would still read the same add what tells them apart, read off the other facets in order (Paper 1 · Higher, Paper 1 · Foundation). | The same rule for every facet replaced the paper's own labels and the year-and-month trimming. | find.js shortLabels_, tellApart_ | TRUE |
| FN-018 | Cards | (tags) |  | display | Every facet is a tag on the card, in the facets' order, coloured by TAG_OF (a default colour for any facet nobody listed). A tag is said as its button would be once every question before it was answered the card's way; a word already on the row, or a tag that is only earlier tags side by side, is not said twice. | A card's tags are the finder's answers, so they read and colour alike. | find.js tagRow_, cardList_, TAG_OF | TRUE |
| FN-019 | Funnel | (answers) |  | rule | What kind's answers are plain filters: Questions, Answers, Practicals, Projects, Content, Resources. Answers keeps a question's answer pages (open), Questions its other pages — by the page's own tag. Bundles is not a kind; the bundle card stands in front of a list of whole papers. | A kind that drew a view of its own was a special case. | find.js stuffPages_, bundlePages_ | TRUE |
| FN-020 | Answers | (any) |  | display | Each answer shows how many items are behind it. | It is the only way to tell a useful question from a pointless one before answering it. | find.js facetValues | TRUE |
| FN-021 | Answers | (any) |  | rule | A cell holding a comma-separated list counts as several answers, not one. Key stage does this. | A primary worksheet serves KS1 and KS2. Forcing one answer means choosing which half of the audience to hide it from. | find.js keystage facet, asList_ | TRUE |
| FN-022 | Answers | (any) |  | display | Answers are rows that look pressable: a surface, a border, a pressed state. | They were text on a line with a number at the end — the same thing a receipt row looks like. | FN-023 | Answers | (any) |  | rule | An option that does not fit is MARKED with the reason and left in the list, never removed. | A list that quietly drops things seems to have decided for you, and the thing it drops is often the one you meant. | find.js, same rule as booking BK-102 | TRUE |
| FN-030 | Items | (global) |  | rule | Papers and worksheets are derived by grouping question rows on paper_id. Storing them twice means keeping them in step by hand. | find.js allTopics | TRUE |
| FN-031 | Items | (global) |  | rule | A worksheet is ONE card. Its questions do not appear as separate cards. | 2,463 worksheet rows across 161 worksheets. | FN-032 | Items | (global) |  | rule | A past paper's questions DO appear as separate cards, alongside the paper. | Question 5 of a past paper is a thing somebody revises and asks for by number. Q17 of a times-tables sheet is not — nobody wants the seventeenth question, they want the sheet. | find.js questionItems, qNumber | TRUE |
| FN-033 | Items | (global) |  | rule | A question row whose kind is 'stem' is never an item. It is the shared preamble for the parts under it. | It has no marks and no answer; it is context, and on its own it reads as a question with the question missing. | find.js | TRUE |
| FN-040 | Search | (box) |  | rule | The search box matches against name, sub, subject, slot, grade AND the text of the question itself. | A question's name is 'Q5b'. | FN-041 | Search | (box) |  | rule | A collapsed worksheet is searchable by the text of every question inside it. | A bearings sheet whose title says nothing about compasses should still be found by 'compass'. | find.js paperText_ | TRUE |
| FN-042 | Search | (box) |  | rule | Search text is built once when items are built, never inside the filter. | The obvious version strips HTML inside the filter, which runs for every item on every letter typed — three thousand regexes a keystroke. | find.js searchText_, memoised on the payload | TRUE |
| FN-050 | Sort | (list) |  | order | Questions sort by their paper first, then by question number as a NUMBER, then by part. | By name alone a question sorts as 'Q5b', so every paper's Q1 clumped together and Q1, Q10, Q11 came before Q2 — in the one list where the sequence is the whole point. | find.js stuffItems sort | TRUE |
| FN-051 | Sort | (list) |  | order | Everything that is not a question falls through to a plain name comparison. | Its sub is empty and its question number is zero, so the tiebreaks pass over it untouched. | find.js | TRUE |
