# geometry

| id | area | kind | rule | because | source | active |
|---|---|---|---|---|---|---|
| GM-01 | Cell | rule | A screen is a cell in a grid. It is positioned by ONE transform: translate(dx * step, shift), where dx is how many columns away it is from the one in front. | Every other way of doing it — left, margin, a flex row — means two things deciding the same position, and they drift the first time one is changed. | shell.js placeNow_ | TRUE |
| GM-02 | Cell | token | step = appWidth * (CARD_W + gap), where gap = max(0.005, 0.5 - CARD_W/2 - EDGE_SHOWING). | The gap is NOT a setting. Across the screen sits edge, gap, card, gap, edge, and they add to 1. Set all three by hand and the cards drift further off centre with every change. | shell.js stepX_ | TRUE |
| GM-03 | Cell | limit | A card wider than 0.80 with an edge wider than 0.08 would overlap. The gap floors at 0.005 instead: the cards stay apart and less of the neighbour shows. | An overlap is the one outcome that looks broken rather than merely tight. | shell.js stepX_ | TRUE |
| GM-04 | Cell | rule | The app is a fixed column of --app (26.5rem), centred. Every width and every step is measured against THAT, never against the window. | On a window wider than the app, a swipe measured against the window had to travel further than the app is wide to register. | style.css --app, shell.js appWidth_ | TRUE |
| GM-05 | Cell | rule | A screen fills the app column's full height. Its pane is what scrolls; the screen itself does not. | Two things claiming to be the scroller is how a fixed bar drifts on iOS. | style.css .screen, .pane | TRUE |
| GM-06 | Cell | rule | ONLY A SLIVER OF A NEIGHBOUR IS VISIBLE — 8% of it, at the edge. Not the whole screen side by side. | This is what GS-07's .92 dimming assumes. What you see of a neighbour is its bright top edge and its border; at .92 that edge reads, at .55 it renders at 30/255 and is drawn but invisible. Neither number means anything if the whole screen is showing. | shell.js, EDGE_SHOWING | TRUE |
| GM-07 | Cell | rule | A screen more than two columns away is display:none, not merely transparent. | Nine screens all in the document is nine screens being laid out on every repaint, for seven nobody is looking at. | shell.js placeNow_ | TRUE |
| GM-08 | Cell | rule | An unplaced screen is visibility:hidden and off to the side, and a hidden element cannot be pressed. | It used to be pointer-events:none turned back on by a class only JavaScript adds — so the app was untouchable by default and depended on code running to become touchable. Any error before the first placement left a dead page. | style.css .screen | TRUE |
| GM-09 | Page | rule | The vertical position is columnShift_(screen, page) — the page being read is slid to the middle. A vertical drag only ever moves the screen in front. | The others have no finger on them. | shell.js placeNow_ | TRUE |
| GM-10 | Page | rule | A screen with ONE page has no vertical axis, and a vertical drag there falls through to ordinary scrolling. | It is what makes a scrolling screen possible with no special case: one page means nothing to page to. | shell.js AXES | TRUE |
| GM-11 | Banner | rule | A banner sits ABOVE the grid and pushes it down. It does not overlay a screen. | A message lying across the top of a card hides the first line of whatever it is warning you about. | style.css .banner | TRUE |
| GM-12 | Order | rule | TABS is append-only. Display order comes from the columns tab, applied by sorting — never by rewriting the list. | AT is remembered by id in localStorage and the axis clamps by index, so reordering the literal moves somebody's remembered position to a different screen on the next boot. | shell.js TAB_ORDER | TRUE |
