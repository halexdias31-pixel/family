# The rulebook — the one foundation

**One source for every truth: every fact, rule and design lives in exactly one place and everything else is generated from it. Only the safety rules stand beside it. Where the rules don't decide, ask the owner.**

Everything below derives from that core: 2 principles (single source of truth, and safety), each with its specific rules. Each rule is stated once, in its current form, with the checks that enforce it after `Checks:`; a check id is a `tools/health.js` rule, `js/check-<id>.js` or `check/<id>.js`, and `flow/*` is every journey in `check/flow/`. A higher principle wins a clash. The rulebook is code: `data/settings/rules.json` is the one source, `node tools/rules.js --write` writes this page from it, and `node tools/rules.js` fails when a rule names no check, a check serves no rule, a named check does not exist, or this page is stale. Superseded decisions and their dates: `docs/history/1213-one-rulebook.md`.

## 2. Safe
- **2.1** The law always wins, silently; a deletion request for personal data beats keeping things.
- **2.2** Private things (learners, money, staff records, library private fields) live only in the owner's Sheets; the public repo holds no real names, emails, PINs, learner data, secrets or model ids.
- **2.3** Private by default: a student sees only themselves and their tutors, a parent their own children, a tutor their own students and their parents, admin everyone.
- **2.4** Check, then trust: actions gated until approval, ID and DBS; staff only by application; one rank per account; three roles (admin, tutor, family).
- **2.5** Parents receive nothing from the site until they tick it; push is device opt-in.
- **2.6** No price reaches a child; no child's surname leaves the server.
- **2.7** Posts and photos wait for approval and are kept as files.
- **2.8** Names on screen are first name + initial for everyone; parents' essential emails go to the admin for now, saying who they were for.
- **2.9** A PIN is never in a URL, the browser history, device storage or any log; it is typed on the site keypad, shown as * tags, and checked only by the server.

## How a sweep works
1. Read this file; read `docs/history` only for the area in hand (`grep -ril <keyword> docs/history`).
2. Questions for the owner are asked in conversation (owner, 18 Nov), never on a card; an answer becomes its change, an edit of the rule it touches here and a history note. A general answer ("always do X") becomes a rule here. A clash becomes a question (1.3).
3. Work the one worklist, dearest first, budgets only going down: `node tools/health.js --list`, `--changed`.
4. Anything the rules don't decide becomes an open question (id, words, options a/b/c), never a guess. Write the guess first; where guesses match the owner's answers ~9 in 10, stop asking there.
5. Stable = the core (Find, Library, Questions, Settings, Bookings) works on a phone with no errors and CI is green 3 runs running; frozen features return one at a time after that, most-used first. The Apps Script deploy stays the owner's.
